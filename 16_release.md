## 3. Как запустить

Полное описание — `docs/admin-guide.md` §2–§3. Требования: Linux x86_64, Docker Engine с Compose v2, `git`, `make`, `openssl`, `uv` (для smoke), доступ к образам `python:3.13-slim`, `node:24-slim`, `postgres:18` или их зеркалу. Эталонный стенд SC-001 — 4 vCPU и 8 ГБ.

```bash
git clone <адрес репозитория> llm-budget && cd llm-budget
cp deploy/.env.example deploy/.env
sed -i "s|^POSTGRES_PASSWORD=.*|POSTGRES_PASSWORD=$(openssl rand -hex 24)|"         deploy/.env
sed -i "s|^SESSION_SECRET=.*|SESSION_SECRET=$(openssl rand -hex 32)|"               deploy/.env
sed -i "s|^ADMIN_INITIAL_PASSWORD=.*|ADMIN_INITIAL_PASSWORD=$(openssl rand -hex 12)|" deploy/.env
chmod 600 deploy/.env
make up                                   # сборка и запуск, ждёт healthy (до 180 с)
# http://127.0.0.1:8080/admin/ → admin / ADMIN_INITIAL_PASSWORD → смена пароля (≥ 12 символов)
make smoke BM_ADMIN_PASSWORD='<новый пароль>'   # путь до первого решения
```

| Действие | Команда |
|---|---|
| Остановить / запустить | `make down` / `make up` |
| Журналы | `make logs` |
| Резервная копия / восстановление | `make backup` / `make restore [FILE=bm-….dump]`, затем `make smoke` |
| Отказоустойчивость SC-002/SC-003 | `make failover BM_ADMIN_PASSWORD='…'` |
| Нагрузка SC-001/SC-004 | `make load` (на простаивающей машине, 50 rps × 600 с) |
| SDL: SBOM, лицензии, уязвимости, Trivy | `CHECK_STRICT=1 make check` |
| Нет исходящего трафика (root) | `sudo make egress-host-check` при `IMPORT_ENABLED=false` |
| Тесты разработчика | `DATABASE_URL=postgresql://… make test`; `make lint` |
| Стек без Docker (разработка) | `make up-local`, `make smoke BM_STACK=local`, `make down-local` |
| Закрытый контур | `docs/admin-guide.md` §13 |
| Один файл без Docker (Linux AppImage, пилот) | `make appimage` → `./LLM_Budget_Manager-0.1.0-x86_64.AppImage`; §3а, `deploy/appimage/README.md` |

Импорт расхода по умолчанию выключен (`IMPORT_ENABLED=false`). Включение — §8–§9. Webhook включается заданием `WEBHOOK_URL` с внутренним IP-адресом (§10). Интеграция вызывающих систем — `docs/integration-guide.md`.

Каждый пункт можно либо выполнить, либо явно принять как есть: ответ «принимаю» и номер пункта.

1. **Стенд заказчика (4 vCPU, 8 ГБ, Docker, доступ к образам):** пройти `docs/admin-guide.md` §14, пункты 1–9, по разделу 3, засечь время от `git clone` до зелёного smoke и приложить вывод команд. Это снимает **SC-009** (≤ 30 мин) и **`egress-host-check`** (п. 8: `пакетов наружу = 0`). Там же `make load` на простаивающей машине поднимает **SC-001** из PASS-замены в PASS.
2. **Импорт с реальными ключами за одни сутки UTC** (§14, п. 10): admin-ключ Anthropic, и OpenAI, если используется, `IMPORT_ENABLED=true`, «Загрузить сейчас». Затем сумма за эти сутки в «Отчётах» сверяется с консолью провайдера. Расхождение около 100 раз — FAIL допущения: сообщить нам дату и обе суммы, `enforce` по импорту не включать. Если разрешите, записанный ответ без ключа заменит синтетические фикстуры.
3. **Юрист заказчика:** подтвердить использование `certifi` 2026.10.19 под MPL-2.0 (файловый копилефт, пакет не модифицируется, приходит транзитивно через `httpx`). Без подтверждения ★-гейт лицензий остаётся НЕ ПРОВЕРЕНО.
4. **Решение по MCP** (`14_checkpoint_week5.md` §5): (а) оставить v1 без MCP; (б) выбрать объём 1В — 2,03 млн ₽, выше порога SC-013; (в) предоставить фактическую стоимость работы агентов, по которой прогноз с MCP укладывается в 4,17 чел.-мес / 2 млн ₽. В вариантах (б) и (в) MCP делается после релиза и начинается с проверки R-5.
5. **Принять известные ограничения** раздела 6, прежде всего npm moderate и `backup` от root.
6. *(Необязательно, 6Р1)* Выгрузить полный журнал CI `gh run view 39663848299 --log` и приложить его к релизу (`deploy/ci/runs/d98ba2d.log`). На статусы не влияет.

Когда п. 1–3 выполнены с PASS или явно приняты, релиз становится безусловным. Отдельная проверка нашей командой для этого не нужна: техлид обновляет этот файл по выводу команд.
