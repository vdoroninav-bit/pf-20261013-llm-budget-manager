**Ответ.** Подтверждено частично. Функции 1–3 в MIT есть, но «недели» и «модель на ключ» требуют проверки. Функция 4 (перенаправление при исчерпании бюджета) из коробки в MIT не доказана. Рекомендация CEO «да, с оговоркой» неточна: оговорка шире, чем «модель-на-ключ». [Вывод]

**Риск расчёта стоимости [Вывод].** Бюджеты считаются в деньгах. Для GigaChat, YandexGPT и vLLM цену токена, вероятно, придётся задавать вручную (`input_cost_per_token` / `output_cost_per_token` в `model_info`), и в ₽, а не в $. ## Как устроено «перенаправление при исчерпании»
- **[Факт]** По умолчанию запрос **отклоняется** (см. п. 3). Модели с нулевой ценой остаются доступны после исчерпания.
- **[Факт]** Перенаправление есть только для per-model бюджетов ключа (`model_max_budget` + `budget_fallbacks`).
- **[Вывод]** Для сценария «у сотрудника кончился бюджет, переключить на дешёвую/собственную модель» в MIT готового механизма нет. Варианты:
  1. Шлюз платформы ловит бюджетную ошибку 4xx и повторяет запрос на другую модель.
  2. Кастомный pre-call hook или callback LiteLLM (расширяемость описана в документации, в этой сессии не проверял).
  3. Взять Enterprise.
- Фолбэк «на ошибку» (4c) для этого не годится: бюджетная ошибка 4xx — не ошибка провайдера.

## Трудоёмкость
Оценка CEO «1–3 чел.-мес. (0,5–1,5 млн ₽)» неявно предполагает ставку ~0,5 млн ₽ за чел.-мес. **[Гипотеза]**, источника нет.

|---|---|
| Разворачивание LiteLLM + Postgres, интеграция со шлюзом и SSO, маппинг подразделение → team | 0,5–1,0 |
| Провайдеры GigaChat / YandexGPT / vLLM, цены токенов, сертификаты, нормализация ошибок | 0,5–1,0 |
| Свой фолбэк при исчерпании бюджета (п. 4a) и тесты | 0,5–1,0 |
| Админ-интерфейс и отчёты (если нужны сверх UI LiteLLM) | 0–1,0 |
| **Итого** | **1,5–4,0** (≈ 0,75–2,0 млн ₽ при 0,5 млн ₽/чел.-мес.) |

Без п. 4a и админки диапазон CEO (1–3) реалистичен. С ними верхняя граница выше. Если брать Enterprise ради `model_max_budget`, добавляется лицензия (цена по запросу, не публичная).
