# Экраны админки LLM Budget Manager v1 (T003)

Вход: `10_tech_spec.md` (US3–US6, FR-027…FR-031), `12_openapi.yaml` 1.0.1 (операции и `x-roles`), `12_tasks.md` (T003, T043, T052, T064, T072), `13_design_rulings.md` (решения техлида В1–В7; перечень правок — `13_design.md` §12). Общие правила, компоненты, тексты ошибок и доступность — в `../13_design.md`. Токены — `tokens.json`.

**Роли в таблицах видимости:** А — администратор (`admin`), В — владелец бюджета (`budget_owner`, только своё подразделение), Ф — наблюдатель-финансист (`finance_viewer`, все подразделения, только чтение, без сотрудников). «—» — экран или блок не показывается и не запрашивается.

**Общие правила для всех экранов**
- Деньги приходят строкой `Money` (`"12345.67"`). Отображение — `12 345,67 ₽`, разделитель групп — неразрывный узкий пробел, минус — знак `−` (U+2212). Строка форматируется без перевода в `float` (принцип VI): разбиваем по точке, группируем целую часть.
- Время показывается по МСК: `15.10.2026, 00:00 МСК`. Даты импорта провайдеров — это сутки UTC провайдера (решение заказчика 4А), рядом с ними пишем «сутки UTC».
- Списки — `{items, total}`, страница по умолчанию 50 строк, максимум 200 (`page_size`).
- Ошибка API — `application/problem+json`. Показываем `detail` с сервера (он на русском); если `detail` нет — текст из словаря `13_design.md` §7 по `code`. Ошибки полей (`errors[].field`) — под соответствующим полем.
- Любой экран при 401 уводит на «Вход» с сообщением «Сессия закончилась. Войдите снова.» и возвращает на исходный адрес после входа.
- Любой экран при 403 показывает состояние «Нет доступа» (компонент `EmptyState`, вариант `forbidden`): «Этот раздел недоступен для вашей роли. Попытка записана в журнал аудита.» Пункты, которые роли недоступны, в меню не показываются вообще, поэтому 403 — это переход по прямой ссылке.

**Матрица FR → экран** (чек-лист приёмки T003)

| Требование | Экран | Блок |
|---|---|---|
| FR-027 лимит, расход по источникам, резервы, остаток, дата сброса, разбивка по моделям, отставание импорта | 2 Панель подразделения | шкалы периодов, «По моделям», плашка импорта |
| FR-028 CSV без идентификаторов сотрудников | 8 Отчёты, CSV и сверка | «Выгрузить CSV» |
| FR-029 уведомления 80% и 100% один раз за период, в админке | 2 Панель (лента), шапка (колокольчик), 11 Журналы → Уведомления | |
| FR-030 роли, локальный вход | 1 Вход, 10 Пользователи админки, меню по ролям | |
| FR-031 журнал аудита | 11 Журналы → Аудит | |

Экраны 9–11 не входят в восьмёрку T003, но нужны для T043 (ключи, пользователи) и T072 (журналы), а также для закрытия FR-030 и FR-031. Они описаны короче и приняты техлидом в этом виде, без отдельных макетов и без расширения объёма (`13_design_rulings.md`, В4).

**Константы интерфейса** (решение техлида В7: значения UI, а не NFR; хранятся в одном модуле frontend):
- 10 с — показ «Загрузка дольше обычного…» и кнопки «Повторить»; запрос при этом не обрывается.
- 60 с — автообновление панели и счётчика колокольчика, только пока вкладка видима (`document.visibilityState === 'visible'`).
- 10 с — обновление «Запусков» импорта, только пока есть строки `queued` или `running`; затем опрос останавливается.
- Отставание импорта — одно правило по SC-008 для панели и экрана 7: если сейчас позже 12:00 МСК, а `last_success_day` раньше вчерашних суток UTC, показывается `warning`. Других порогов отставания нет.

## 1. Вход

**Сценарий:** FR-030, предусловие всех потоков. **Маршрут:** `/admin/#/login`, `/admin/#/password`.
**Операции:** `login`, `me`, `changePassword`, `logout`.

**Видимость:** экран доступен без входа; смена пароля — любой роли.

### 1.1 Форма входа
| Поле | Тип | Подпись | Валидация | Пример |
|---|---|---|---|---|
| login | текст, `autocomplete=username` | Логин | обязательно | `ivanova` |
| password | пароль, `autocomplete=current-password`, кнопка «Показать пароль» | Пароль | обязательно | — |

Действие: **«Войти»** (основная кнопка, Enter в любом поле). Пока идёт запрос, кнопка выключена и показывает «Входим…».
После `200` ответ `Session`: `csrf_token` сохраняется в памяти (не в localStorage) и уходит в `X-CSRF-Token`. Если `user.must_change_password = true` — сразу на 1.2, иначе на «Панель».

Над формой — название «Бюджеты LLM» и строка «Учёт и лимиты расходов на языковые модели». Никаких логотипов и картинок по внешним адресам.

**Состояния**
- Загрузка: кнопка «Входим…», поля доступны только для чтения.
- `401 invalid_credentials`: «Неверный логин или пароль.» под формой, фокус возвращается в поле «Пароль», пароль очищается.
- `429 login_locked`: «Слишком много неудачных попыток. Вход для этой учётной записи закрыт на 15 минут. Если пароль забыт, обратитесь к администратору.» Кнопка «Войти» остаётся активной.
- Сеть недоступна или 5xx: «Сервер не отвечает. Проверьте, что утилита запущена (`make up`), и попробуйте ещё раз.»

### 1.2 Смена пароля
Открывается принудительно при первом входе и из меню пользователя («Сменить пароль»).

| Поле | Подпись | Валидация |
|---|---|---|
| old_password | Текущий пароль | обязательно |
| new_password | Новый пароль | не короче 12 символов (`minLength: 12`) |
| (только UI) | Повторите новый пароль | совпадает с новым |

Подсказка под полем: «Не короче 12 символов».
Действие: **«Сменить пароль»** → `204` → уведомление «Пароль изменён» → «Панель».
При принудительной смене кнопки «Отмена» нет, есть только «Выйти».
Ошибки: `422` — текст под полем из `errors[]`; `401` — «Текущий пароль указан неверно.»

### Поля шкалы периода (`LimitBalance`, компонент `PeriodBudgetMeter`)
| Подпись | Поле | Формат |
|---|---|---|
| Сутки / Неделя / Месяц | `period` | `day` → «Сутки», `week` → «Неделя», `month` → «Месяц» |
| Лимит | `limit_rub` | `лимит 60 000,00 ₽` |
| Подписки | `spent.subscriptions_rub` | сегмент, `src-subscription` |
| Импорт | `spent.import_rub` | сегмент, `src-import` |
| Токены | `spent.token_rub` | сегмент, `src-token` |
| Резервы | `reserved_rub` | сегмент со штриховкой `reservation-hatch` |
| Остаток | `remaining_rub` | крупно; если `< 0` — подпись «Перерасход», цвет `danger`, на шкале выход за отметку лимита со штриховкой `over-hatch` |
| Использовано | `used_pct` | `78,4%` в подсказке и в `aria-label` |
| Сброс | `resets_at` | `сброс 01.11, 00:00 МСК` |
| Начало периода | `period_start` | в подсказке: «Период с 01.10.2026» |
| Доля подписок | `subscriptions_share_pct` | если ≥ `Department.subs_warn_pct` — пометка «Подписки занимают 52,0% бюджета периода» (`warning`). Процент разбирается из строки без `float` и используется только для этого текста и сравнения с порогом |
| Бюджет занят подписками | `spent.subscriptions_rub`, `limit_rub` | признак = `spent.subscriptions_rub > 0` **и** `spent.subscriptions_rub ≥ limit_rub`; обе суммы сравниваются как целые копейки после разбора строки, без `float`. По `subscriptions_share_pct` признак не вычисляется (при 99,95–99,99% там `100.0`, а вызовы ещё проходят). Если признак есть — «Бюджет занят подписками: платные вызовы получают отказ» (`danger`); вместо пометки о доле. При лимите `0.00` без подписок признака нет |

Отметка 80% — тонкая вертикальная линия `meter-threshold` (порог FR-029). Шкала строится в масштабе `max(limit, spent+reserved)`, так что перерасход виден как выход за правый край лимита.

Владелец лимитов — подразделение (`owner_type=department`). Шкалы выводятся в порядке день, неделя, месяц; периоды, для которых лимит не задан, не показываются.

### Блок «Из чего сложился расход»
Переключатель периода (Сутки / Неделя / Месяц) над блоком, по умолчанию «Месяц». Четыре строки сумм из `LimitBalance` выбранного периода. Кнопка **«Показать строки»** у каждой строки открывает таблицу `listDepartmentBalanceItems?period=&source=`:

| Колонка | Поле | Примечание |
|---|---|---|
| Дата | `date` | для `import` — с пометкой «сутки UTC» |
| Источник | `source` | словарь `13_design.md` §7.3 |
| Модель | `model_id` | моноширинный |
| Сотрудник | `subject_pseudonym` | только А и В; псевдоним, у А — кнопка «Кто это?» (экран 3, раскрытие псевдонима) |
| Сумма | `amount_rub` | справа |
| Пометки | `flags` | чипы: «Нет отчёта», «Решение не выполнено»… |

### Блок «По моделям»
`getSpendReport?from=<period_start>&to=<сегодня>&department_id=<id>&group_by=model,source`. Колонки: Модель, Источник, Сумма (₽), Исходная сумма (если `original_currency = USD`: `128,40 $`). Итог — `total_rub`. Строки с `late = true` — чип «Поздний импорт».

### Плашка импорта (А, В, Ф)
По каждому провайдеру из `ImportStatus.providers`:
- `enabled = false`: «Импорт расхода провайдеров выключен. Расход Anthropic и OpenAI попадает в бюджет только через Decision API.» (нейтральный стиль).
- `configured = false`: «OpenAI: ключ администратора не задан.»
- норма: «Anthropic: загружено по 13.10 (сутки UTC), отставание 16 ч.» `lag_hours` выводится числом, своего порога у него нет.
- `consecutive_failures ≥ 2`: `danger`, «Anthropic: 2 загрузки подряд не удались. Последняя успешная — 11.10. Подробности — в разделе «Импорт провайдеров».» Ссылка на экран 7 только для А.
- отставание по SC-008 (единственный порог, тот же на экране 7): если сейчас позже 12:00 МСК, а `last_success_day` раньше вчерашних суток UTC — `warning`, «Данные за вчера ещё не загружены.»

**Отличия для владельца бюджета (В)** (решение В1):
- тексты те же, что у А и Ф, но ссылки на экран 7 нет — плашка не кликабельна;
- при `consecutive_failures ≥ 2` вместо «Подробности — в разделе «Импорт провайдеров».» пишется «Администратор получил уведомление.»;
- класс ошибки и несопоставленные источники не показываются (в ответе для В их нет: `last_error_class = null`, `unallocated_sources = []`);
- пункта меню «Импорт провайдеров» у В по-прежнему нет.

### Состояния
- **Загрузка:** скелет трёх шкал и двух таблиц той же высоты (без прыжков вёрстки). Если ответ дольше 10 с — под скелетом «Загрузка дольше обычного…» и кнопка «Повторить»; запрос не обрывается. [Решение техлида В7, значения UI.]
- **Нет подразделений** (`listDepartments.total = 0`): А — «Подразделений пока нет. Загрузите выгрузку групп AD или создайте подразделение вручную.» Кнопки «Загрузить файл AD» (экран 6), «Создать подразделение» (экран 3). Ф — «Подразделений пока нет. Их создаёт администратор.»
- **Владелец бюджета без подразделения** (`user.department_id = null`): «Ваша учётная запись не привязана к подразделению. Обратитесь к администратору.»
- **Лимиты не заданы** (`limits = []`): «Для подразделения не заданы лимиты — расход не ограничивается.» А — кнопка «Задать лимиты» (экран 3). Блоки «Из чего сложилось» и «По моделям» всё равно показываются: расход учитывается и без лимита.
- **Нет расхода за период:** шкала пустая, остаток = лимит; «По моделям» — «За этот период расхода нет».
- **Режим «Наблюдать» или «Предупреждать» при перерасходе:** под шкалой — «Режим «Наблюдать»: вызовы не блокируются, превышения записываются в журнал.»
- **Частичные данные:** если `getDepartmentBalance` ответил, а `getSpendReport` или `getImportStatus` — нет, шкалы показываются, на месте упавшего блока — `ProblemAlert` «Не удалось загрузить разбивку по моделям. [Повторить]».
- **Ошибка шкал:** `ProblemAlert` на всю ширину, «Не удалось посчитать остатки. [Повторить]».
- **403** (В открыл чужое подразделение по ссылке): состояние «Нет доступа».

Обновление: кнопка «Обновить» и автоматически раз в 60 с, только пока вкладка видима (`document.visibilityState === 'visible'`) [Решение техлида В7, значения UI: совпадает с `refresh_s` и минутным циклом фоновых задач]. Время расчёта (`as_of`) видно в шапке панели.

## 3. Подразделения и лимиты

### 3.1 Список
Колонки: Название (`name`), Группа AD (`ad_group`, «—» если создано вручную), Режим (`policy_mode`), Если утилита недоступна (`fail_mode`), Сутки / Неделя / Месяц (`limits.day|week|month`, «нет лимита» при `null`), Сотрудников (`employees_count`).
Поиск: поле «Найти подразделение» → `q`. Сортировка по названию.
У В список из одной строки — сразу открывается карточка.

### 3.2 Карточка подразделения (вкладка «Настройки»)
| Поле | Тип | Подпись | Валидация / подсказка | Пример |
|---|---|---|---|---|
| name | текст | Название | 1–200 символов | «Маркетинг» |
| ad_group | только чтение | Группа AD | — | `CN=AI-Marketing` |
| policy_mode | радиокнопки | Режим | «Наблюдать — вызовы не блокируются, превышения пишутся в журнал. Предупреждать — то же, плюс пометка в ответе. Ограничивать — отказ или перенаправление на более дешёвую модель.» | Ограничивать |
| fail_mode | радиокнопки | Если утилита недоступна | «Пропускать вызовы (рекомендуется)» / «Блокировать вызовы» | Пропускать |
| allowed_models | множественный выбор из `listModels` | Разрешённые модели | Если список пуст — предупреждение `warning`: «Ни одна модель не разрешена: все вызовы получат отказ «Модель не разрешена».» | gigachat-pro, yandexgpt-lite |

## 6. Загрузка выгрузки групп AD со сводкой

**Сценарий:** US3.1, US3.2; FR-012. **Маршрут:** `/admin/#/org-import`. **Операция:** `importOrg` (сначала `dry_run=true`, затем `false`).
**Видимость:** только А. В меню у В и Ф пункта нет.

### Шаги (настоящая последовательность, поэтому с номерами)
1. **Выбор файла.** Компонент `FileDropzone`: «Перетащите CSV-файл сюда или [выберите файл]». Принимается `.csv`.
   Справка под зоной (раскрывается «Формат файла»):
   ```
   login;display_name;group;is_primary
   ivanova;Иванова А. С.;AI-Marketing;1
   ivanova;Иванова А. С.;AI-Analytics;0
   petrov;Петров И. И.;AI-Analytics;
   ```
   «Кодировка UTF-8, разделитель — точка с запятой. is_primary — 1, 0 или пусто: так отмечается основная группа сотрудника. Размер — не больше 10 МБ.»
2. **Проверка.** Сразу после выбора файл отправляется с `dry_run=true`. Показ: «Проверяем файл…». Ничего не меняется.
3. **Сводка проверки** (`OrgImportSummary`, компонент `ImportSummary`):
   | Подпись | Поле |
   |---|---|
   | Строк в файле | `rows_total` |
   | Будет применено | `rows_applied` |
   | Новых подразделений | `departments_added` |
   | Новых сотрудников | `employees_added` |
   | Изменено | `employees_updated` |
   | Переведено в другое подразделение | `employees_moved` |
   | Будет выведено из подразделений (нет в файле) | `employees_removed` — если > 0, `warning` |
   | Ошибки строк | `errors[]` — таблица «Строка / Что не так», `danger` |
   | Предупреждения | `warnings[]` — таблица «Строка / Предупреждение», например «Нет отметки основной группы — выбрана первая по порядку» |
   Подпись: «Строки с ошибками не применяются, остальные применяются.»
4. **Применение.** Кнопка **«Применить изменения»** (тот же файл, `dry_run=false`). Если `employees_removed > 0` — `ConfirmDialog`: «12 сотрудников будут выведены из подразделений, потому что их нет в файле. Их расход за текущий период сохранится. Продолжить?» Кнопка «Выбрать другой файл» сбрасывает шаги.
5. **Результат.** Та же сводка с заголовком «Изменения применены» и ссылками «К подразделениям», «Задать лимиты». Выгрузки ошибочных строк файлом нет (в контракте её нет), таблицу ошибок можно выделить и скопировать.

### Состояния
- Файл больше 10 МиБ (10 485 760 байт) — проверка на клиенте сразу после выбора, до отправки; файл не отправляется: «Файл больше 10 МБ. Выгрузка групп AD обычно гораздо меньше — проверьте, что выбран нужный файл.» Тот же текст при ответе сервера `413 file_too_large`; ничего не применяется. Отдельного лимита строк нет (решение В6). В справке «Формат файла» добавлена строка «Размер — не больше 10 МБ».
- Файл не CSV или пустой → `422`: «Файл не похож на выгрузку групп: проверьте заголовок `login;display_name;group;is_primary` и кодировку UTF-8.» (или `detail` с сервера).
- Все строки с ошибками (`rows_applied = 0`): кнопка «Применить» выключена, подпись «Применять нечего — исправьте файл и загрузите снова.»
- Сеть пропала на шаге 4: «Не удалось применить изменения. Неизвестно, успели ли они сохраниться: загрузите файл ещё раз в режиме проверки — сводка покажет, что осталось изменить.»
- Повторная загрузка того же файла после применения: сводка с нулями — «Изменений нет, оргструктура совпадает с файлом.»
- 403 — «Нет доступа».

### Видимость

### 7.1 Вкладка «Состояние»
Общая строка: `enabled` → «Импорт включён» (`success`) или «Импорт выключен» с пояснением: «Импорт включается переменной окружения IMPORT_ENABLED на сервере. Пока он выключен, утилита не обращается в интернет.»
По каждому провайдеру (Anthropic, OpenAI) — панель:

| Подпись | Поле | Формат |
|---|---|---|
| Ключ администратора | `configured` | «Задан» / «Не задан — задайте ANTHROPIC_ADMIN_KEY на сервере». Значение ключа не показывается никогда |
| Загружено по | `last_success_day` | `13.10.2026 (сутки UTC)` |
| Последний запуск | `last_run_at` | `14.10.2026, 09:00 МСК` |
| Отставание | `lag_hours` | `16 ч` — число без собственного порога. `warning` «Данные за вчера ещё не загружены» — только по правилу SC-008, общему с панелью: сейчас позже 12:00 МСК, а `last_success_day` раньше вчерашних суток UTC (решение В7) |
| Неудач подряд | `consecutive_failures` | 0 — не показывается; ≥ 2 — `danger` «Администратор получил уведомление» |
| Ошибка | `last_error_class` | `ImportErrorClass`: `auth_rejected`, `provider_unavailable`, `bad_response`, `internal` → текст по словарю `13_design.md` §7.4; исходный класс — мелко моноширинным; значение вне перечня — «Загрузка не удалась» и класс моноширинным; `null` — строка не показывается |
| Несопоставленные источники | `unallocated_sources[]` | список `ref` моноширинным + кнопка «Сопоставить» → форма источника с заполненным `ref` |

Кнопка **«Загрузить сейчас»** (А) → диалог: Провайдер (фиксирован), «С» и «По» (сутки UTC, необязательно; подсказка «Пусто — окно по умолчанию») → `runImport` → `202` → «Загрузка поставлена в очередь» и переход на «Запуски» с новой строкой `queued`.
`409 import_disabled` → «Импорт выключен на сервере (IMPORT_ENABLED=false). Включите его в окружении и перезапустите утилиту.» `409 provider_key_missing` → «Ключ администратора OpenAI не задан на сервере.» Кнопка выключена заранее, если `enabled = false` или `configured = false`, с той же подсказкой.

### 7.2 Вкладка «Источники»
Подпись: «Каждому источнику провайдера — ровно один способ учёта. «Списывать» — расход импорта уменьшает бюджет подразделения. «Только сверка» — вызовы уже идут через Decision API, импорт нужен для отчёта сверки.»
Колонки: Провайдер, Тип (`kind`), Идентификатор у провайдера (`ref`, моноширинный), Название (`display_name`), Подразделение, Способ учёта (`mode`).

Форма источника (А):
| Поле | Подпись | Валидация / подсказка |
|---|---|---|
| provider | Провайдер | Anthropic / OpenAI |
| kind | Тип источника | Workspace / Проект / Ключ API; для Anthropic доступен только Workspace (остальные выключены с подсказкой «Anthropic отдаёт расход только по workspace»). После создания не меняется |
| ref | Идентификатор у провайдера | 1–200; пример `wrkspc_01AbC…` (Anthropic), `proj_abc123` (OpenAI). После создания не меняется |
| display_name | Название | необязательно, до 200 |
| department_id | Подразделение | обязательно |
| mode | Способ учёта | «Списывать из бюджета (импорт)» / «Только сверка (Decision API)» |

Ошибки: `409 source_exists` → «Этот источник уже есть в справочнике. У источника может быть только один способ учёта — измените существующую запись.» `422 unsupported_source_kind` → «Для Anthropic можно добавить только workspace.»
Изменение способа учёта или подразделения → «Сохранено. Статусы загруженных строк пересчитаются при следующей загрузке.»
Удаление → `ConfirmDialog`: «Удалить источник? Его расход станет «Не распределено» при следующей загрузке и перестанет списываться из бюджета.»

### 7.3 Вкладка «Запуски»
`listImportRuns`, фильтр по провайдеру. Колонки: Провайдер, Статус (`queued` «В очереди», `running` «Идёт», `ok` «Успешно», `failed` «Ошибка»), Начат, Завершён, Сутки (`day_from`–`day_to`, UTC), Списано строк (`lines_charged`), Для сверки (`lines_reconcile`), Не распределено (`lines_unallocated`), Изменено провайдером (`lines_changed`), Ошибка (`error_class`: текст по `ImportErrorClass`, `13_design.md` §7.4, и класс моноширинным).
Пока есть строки `queued`/`running`, список обновляется раз в 10 с; когда их нет, опрос останавливается [Решение техлида В7, значения UI].

### Состояния
- Импорт выключен и источников нет: «Импорт расхода провайдеров не используется. Это нормально, если все вызовы идут через Decision API.»
- Источников нет (А): «Справочник пуст. Добавьте workspace Anthropic или проекты OpenAI и выберите способ учёта.» [Добавить источник]
- Запусков нет: «Загрузок ещё не было. Первая выполнится автоматически в час, заданный на сервере (IMPORT_HOUR_MSK).»
- Загрузка, 403 — по общим правилам.

## 10. Пользователи админки (вспомогательный, T043)

**Сценарий:** US6, FR-030. **Маршрут:** `/admin/#/admin-users`. **Операции:** `listAdminUsers`, `createAdminUser`, `updateAdminUser`. **Видимость:** только А.

Колонки: Логин, Роль («Администратор» / «Владелец бюджета» / «Наблюдатель-финансист»), Подразделение (для владельца бюджета), Активен, «Должен сменить пароль».
Форма: Логин (1–128, после создания не меняется), Роль (радиокнопки с пояснением прав каждой роли), Подразделение (обязательно и видно только для «Владелец бюджета»), Временный пароль (≥ 12; подсказка «Пользователь сменит его при первом входе»).
Изменение: роль, подразделение, активность («Отключить вход»), «Задать новый временный пароль» (`reset_password`).
Ошибки: `409 conflict` → «Пользователь с таким логином уже есть.»; `422` без подразделения у владельца → «Выберите подразделение владельца бюджета.»

**Защита последнего администратора** (решение В6). Если пользователь — единственный с `role=admin` и `active=true`, в его карточке выключены переключатель «Отключить вход» и выбор роли, отличной от «Администратор»; подсказка у обоих: «Это единственный активный администратор. Сначала назначьте другого.» Отключить себя можно, если есть другой активный администратор. Если сервер всё же ответил `409 last_admin` (например, другой администратор параллельно отключил второго), изменение не применено: «Нельзя оставить систему без активного администратора.», форма перечитывает пользователя.
