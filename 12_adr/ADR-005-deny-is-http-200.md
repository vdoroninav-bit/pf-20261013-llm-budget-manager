# ADR-005. Отказ — штатный результат решения: HTTP 200 с `outcome=deny` и `http_status_hint`

`POST /api/v1/decisions` на любое решение отвечает 200: `allow`, `redirect` или `deny`. Код отказа передаётся в `code`, подсказка для шлюза — в `http_status_hint` (403, 422 или 429). Так отказ нельзя спутать со сбоем утилиты. Сбой (таймаут, 5xx) по эталонной схеме ведёт к fail-open, и интеграция, которая ловит любые не-2xx как сбой, молча пропускала бы запрещённые вызовы. Форма ответа совпадает с MCP, где отказ — тоже результат, а не ошибка инструмента (FR-002, FR-033). Ошибками (4xx/5xx с `application/problem+json`) остаются только ошибки запроса и доступа: 401, 403 `subject_out_of_scope`, 422 validation.

## Considered Options

- 403 и 429 как HTTP-статусы (classic): буквальнее по спецификации («по смыслу HTTP 403/429»), но создаёт риск fail-open на отказе. Решение за заказчиком (APPROVAL, вопрос 6). При варианте Б меняется только маппинг в адаптере `http`.
