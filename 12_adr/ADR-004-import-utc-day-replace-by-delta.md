# ADR-004. Импорт: сутки UTC провайдера = дата расхода, замена через дельту, ровно один способ учёта на источник

Cost API Anthropic и Costs API OpenAI отдают стоимость только суточными корзинами [Факт: `11_arch_classic.md` §2, ссылки на документацию провайдеров]. Корзины, судя по примерам, в UTC [Вывод]. Поэтому корзина `[D 00:00Z, D+1 00:00Z)` считается расходом даты D. Строка импорта уникальна по (provider, source_ref, model, day). Перезагрузка за последние `IMPORT_WINDOW_DAYS` (по умолчанию 7 [Гипотеза]) при изменении суммы пишет в `ledger_daily` дельту (новое − старое) в той же транзакции. Так выполняется FR-024: значение заменяется, а не добавляется. У источника ровно один `mode`: `import` — списывается, `decision_api` — только сверка (статус `reconcile`), несопоставленный — `unallocated`.

## Consequences

- Сдвиг относительно МСК — 3 часа. Сверка SC-005 агрегирует события Decision API тоже по суткам UTC. Решение за заказчиком (APPROVAL, вопрос 4).
- Для Anthropic источник — только workspace: `cost_report` не разбивает стоимость по ключам [Факт].
- Если поменять `mode` источника, при следующей перезагрузке статус строки пересчитается, а в реестр уйдёт дельта.
